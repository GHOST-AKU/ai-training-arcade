# 玩法与界面修复记录

## 发现的问题

- 原有难度测试仅验证指定参数能过关、坏的默认参数不能过关。线性回归和神经网络的多数抽样组合都能通过；提高每轮更新数可以绕过轮次预算。
- GBM 和 SVM 按参数阈值人为制造噪声并禁止通关，导致得分达标仍不通过。
- 失败提示要求调参后重置，重置却覆盖玩家的参数。
- GBM 的部分关卡预设值和已知解不在滑块的步长网格上；VM 测试没有模拟浏览器的 range 控件。GBM 改为 0.01 步长，树阈值也改为 0.01，已知解可用键盘或滑块输入。
- 控制按钮排在多段说明之后；默认展开的次要内容、全屏强制横屏遮罩、彩色光晕干扰主任务。

## 玩法变化

- GBM 按分段数、线性回归按梯度更新次数、神经网络按 epoch、森林按分配的树容量计费。规则、已用额度和下一步费用均显示在关卡与控制区。森林费用是明确的游戏容量预算，不是运行时间测量。
- 拒绝超预算操作时不改变模型。手动与自动训练共用判定，撤销同时退还费用。
- 重试保留参数；切换关卡恢复该关初始配置。关卡仍可自由选择。
- 移除 GBM/SVM 的人为噪声、参数组合禁胜和屏幕故障效果。GBM 使用实际的加法更新，不用截断预测值隐藏过大的步幅。
- SVM 增加固定、可见的验证点。验证点从不参与权重更新；训练得分与验证正确率同时达标才通关。软间隔关鼓励简单边界，圆环关需要更弯曲的边界。这里的验证点是玩家可见的关卡目标，不是保密测试集，也不用于宣称真实泛化性能。
- 逻辑回归的 L2 梯度不再被样本数重复缩小；相应重新校准参数范围和已知解。
- K-Means 的质心数量、稳定移动量要求，以及森林至少三棵树的要求现在明确写出。
- 通关状态独立于临时提示，不会因切换视图而消失。目标指标向未达标方向保留小数，避免四舍五入造成“看起来达标却不能通关”。K-Means 重试保留固定评分基准。

## 界面与语言

- 纯色底、克制的扫描线和像素边框，移除彩色背景光晕。
- 画布上方切换观察视图；侧栏先展示目标与操作，原理和详细统计折叠。
- 导航使用算法选择框；同一组内保留一个主题按钮和一个中英切换按钮。
- 中英文覆盖九个页面、无障碍标签、关卡说明、提示、日志和 Canvas 文字。语言和主题保存到本地；语言切换不重载页面或训练状态。
- 使用本地 Fusion Pixel 12px 简体中文字体，覆盖中英文。字体来自 2026.09.01 发布版，随附 OFL 及上游许可证，无第三方字体请求。
- 取消竖屏禁用；神经网络与森林在窄画布中上下分区。

## 验证与范围

全程仅检查代码、事件、DOM 和数值，没有查看或生成截图、没有使用视觉识别。

- `npm test`：语法、结构契约、原有模型 smoke、全关卡可达性、参数空间采样、预算、撤销、重试和翻译覆盖。
- `scripts/dom-qa.cjs`：JSDOM 中加载九个页面，通过实际控件完成 26 关，测试主题、语言切换、日志弹层、所有观察视图和失败路径，并检查传入 Canvas 文本 API 的文字。Canvas 绘图方法是 stub，不验证像素输出。
- 采样结果见 `playability-report.json`。按控件允许值均匀选取固定参数组合，整局保持同一组合；这不是随机玩家通关率，不覆盖所有逐轮自适应策略。教程允许较容易通过。
- 所有挑战关均有已知解；每个算法都存在不能通过的参数组合，且没有任何算法能用“所有滑块拉满”打通其全部挑战关。
- 没有进行视觉验收或真人试玩。浏览器安装下载失败，故不声称通过真实浏览器布局或渲染测试；JSDOM 不计算屏幕布局。整体趣味性仍需要玩家实际反馈。

## 本地复现

无需安装依赖即可运行 `npm test` 和静态站点。

```sh
npm test
npm run playability -- --report
npm run serve
```

DOM 回归是可选开发依赖，不影响静态站点：

```sh
npm install --no-save --package-lock=false jsdom@30.1.0
# 另一个终端保持 npm run serve
npm run qa:dom
```
